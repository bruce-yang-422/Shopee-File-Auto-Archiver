# PNG 輸出與歸檔管理規格

本文件提供給後續 AI 或 Python 程式修改者閱讀。

## 目標

修改報表輸出程式：每次產生新 PNG 前，先歸檔 `00_LINE待發` 中同類型的上一版，再將新圖放入待發區。不得改動既有 CSV、XLSX 自動刪除機制。

## 適用路徑

```text
\\ycpl-server\a02_電商部\03_平台管理\Online_Platform_Data\01_Shopee\04_Report_Output\png
```

## 目標資料夾結構

```text
png/
├─ 00_LINE待發/
├─ 01_LINE已發歸檔/
│  └─ YYYY年MM月/
├─ 02_其他報表/
├─ 03_待確認/
└─ 90_管理資料/
```

只有 `01_LINE已發歸檔` 按月份建立下一層；不建立每日資料夾，也不按報表種類分資料夾。

## 每日 LINE 報表與命名

### 店家訂單數日報

```text
店家訂單數日報_統計YYYYMMDD-YYYYMMDD_產出YYYYMMDD_HHMMSS.png
```

範例：

```text
店家訂單數日報_統計20260815-20260915_產出20260904_100545.png
```

程式也必須相容辨識舊格式：

```text
monthly_order_count_by_shop_YYYYMMDD-YYYYMMDD_YYYYMMDD_HHMMSS.png
```

### 跨平台關注群組數量報表

目前格式：

```text
跨平台關注群組數量報表_YYYYMMDD-YYYYMMDD.png
```

建議新格式：

```text
跨平台關注群組數量報表_統計YYYYMMDD-YYYYMMDD_產出YYYYMMDD_HHMMSS.png
```

## 核心處理流程

每一種報表必須分開處理：

1. 建立或確認管理資料夾存在。
2. 判斷本次要產出的報表類型。
3. 在輸出新圖前，只尋找 `00_LINE待發` 中相同報表類型的上一版。
4. 將同類型上一版移至 `01_LINE已發歸檔/YYYY年MM月`。
5. 產生新的 PNG 暫存檔。
6. 驗證暫存檔成功後，才改為正式檔名並放入 `00_LINE待發`。
7. 將結果寫入歸檔紀錄。

不得在輸出任一報表時清空整個待發資料夾。例如產生店家訂單數日報時，只能歸檔上一張店家訂單數日報，不得移動跨平台報表。

## 歸檔月份判斷

依下列順序決定 `YYYY年MM月`：

1. 優先使用檔名中的產出日期。
2. 舊版跨平台檔名沒有產出時間時，使用統計結束日期。
3. 檔名無法解析時，使用檔案最後修改日期，並在紀錄中標記。

歸檔時保留完整原檔名，以保留統計期間與產出時間。

## 待發區規則

正常情況下，`00_LINE待發` 最多保留：

- 1 張最新店家訂單數日報
- 1 張最新跨平台關注群組數量報表

本流程採用的業務假設是：下一版開始產生時，待發區中的同類型上一版已經傳送到 LINE，因此可移入已發歸檔。若此假設不成立，程式應改成由人工確認發送後才歸檔。

## 新檔安全驗證

新 PNG 必須先寫入暫存檔，並確認：

- 檔案存在
- 檔案大小大於 0
- PNG 可以正常開啟
- 檔名符合規範

驗證成功後再以原子方式改成正式檔。若輸出失敗，不得產生空白正式檔，也不得刪除或覆蓋已歸檔檔案。

## 同名與重複檔案

禁止直接覆蓋歷史歸檔：

1. 同名且內容雜湊相同：保留歸檔既有檔，將待處理檔移至 `03_待確認`，記錄「內容重複」。
2. 同名但內容不同：檔名補上 `_重複YYYYMMDD_HHMMSS`，移至 `03_待確認`。
3. 不得靜默刪除、取代或覆蓋任何歷史檔。

## 其他報表與待確認

`02_其他報表` 只放不需每日傳 LINE 的 PNG，例如臨時分析、測試輸出、物流統計圖片或主管臨時要求圖表。

下列檔案移入 `03_待確認`：

- 檔名無法解析
- 日期不合理
- 同名但內容不同
- 內容完全重複
- 無法判斷是否已發送
- 圖片損毀或無法開啟

## 首次整理既有 PNG

第一次導入時執行一次性整理：

1. 只掃描 `png` 根目錄的 PNG，不遞迴掃描管理子資料夾。
2. 辨識兩種每日 LINE 報表。
3. 依產出日期或統計結束日期歸入對應月份。
4. 每一種類最新一張是否留在待發區，必須先讓使用者確認是否尚未傳送。
5. 無法辨識或有衝突的檔案移至待確認。
6. 實際移動前先產生預覽清單或支援 `dry_run=True`。

第一次整理及日常流程都不得直接刪除現有歷史 PNG。

## 管理紀錄

程式應追加寫入：

```text
png/90_管理資料/PNG歸檔紀錄.csv
```

建議欄位：

```text
處理時間,報表類型,動作,原始路徑,目標路徑,統計開始日,統計結束日,產出時間,檔案大小,結果,備註
```

動作至少包含：輸出、歸檔、移至待確認、發現重複、驗證失敗。

寫入紀錄失敗不應造成報表程式整體中斷，但必須輸出清楚警告。

## CSV 與 XLSX 限制

`csv`、`xlsx` 已有 Python 檔案數量刪除機制，因此：

- 維持原路徑與單層結構。
- 不新增年月子資料夾。
- 不把管理文件放進這兩個資料夾。
- 建議按報表類型分別計算保留數量，避免某類報表產出較多而擠掉其他類型。
- `.~lock.*.csv#` 不得計入正式 CSV 數量。
- 不得刪除正被 Excel、LibreOffice 或其他程序占用的檔案。

## 建議 Python 函式

```python
ensure_png_directories()
detect_report_type(filename)
parse_report_dates(filename)
archive_previous_pending(report_type)
validate_png(path)
write_archive_log(...)
publish_new_png(report_type, output_path)
```

路徑處理應使用 `pathlib.Path`，移動使用 `shutil.move` 或同等安全方式。所有來源和目標都必須確認位於 `04_Report_Output/png` 之下。

## 禁止事項

- 不使用無限制萬用字元刪除。
- 不遞迴刪除資料夾。
- 不覆蓋歷史歸檔。
- 不因單一異常檔案中斷其他報表產出。
- 不把另一種尚未更新的待發報表提前歸檔。
- 未提供預覽前，不批次移動既有 300 多張歷史 PNG。

## 驗收條件

1. `csv`、`xlsx` 原有輸出與清理機制正常。
2. 每種新報表輸出前，只歸檔同類型上一版。
3. 待發區最多各保留一張兩種每日報表。
4. 歸檔月份判斷正確。
5. 同名檔案不會被覆蓋。
6. PNG 輸出失敗時保留可追查訊息。
7. 所有移動與輸出都有歸檔紀錄。
8. 第一次整理既有檔案前先提供預覽，不直接移動或刪除。
